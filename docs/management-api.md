
# Management API

The RackOS Management API provides an HTTP interface for
retrieving appliance information and managed device status.

## Connection

Default base URL:

    http://127.0.0.1:8080

The listening address is configured through the
`RACKOS_HTTP_ADDR` environment variable.

Only explicit loopback IP addresses are permitted.

The Management API currently uses HTTP without administrator
authentication. Remote access is not supported.

Do not expose the API through a reverse proxy or port forwarding.

## Endpoints

| Method | Endpoint | Description |
| --- | --- | --- |
| GET | `/healthz` | Appliance liveness |
| GET | `/readyz` | Appliance readiness |
| GET | `/api/v1/version` | Appliance version |
| GET | `/api/v1/devices` | List registered devices |
| GET | `/api/v1/devices/{id}` | Retrieve a device |
| GET | `/api/v1/devices/summary` | Device status counts |

## List Devices

    GET /api/v1/devices

Returns all registered devices.

Example response:

```json
{
  "devices": [
    {
      "id": "12345678-1234-4000-8000-123456789abc",
      "hostname": "workstation.local",
      "os": "darwin",
      "architecture": "arm64",
      "agent_version": "0.1.0-dev",
      "status": "online",
      "created_at": "2026-11-26T12:00:00Z",
      "updated_at": "2026-11-26T12:05:00Z",
      "last_seen_at": "2026-11-26T12:05:00Z"
    }
  ],
  "total": 1
}
```

An appliance without registered devices returns:

```json
{
  "devices": [],
  "total": 0
}
```

## Retrieve Device

    GET /api/v1/devices/{id}

Returns a single device using its registered device ID.

The response uses the same device representation as the
device list endpoint.

An unknown device returns HTTP 404.

## Device Summary

    GET /api/v1/devices/summary

Returns aggregate device status counts.

Example response:

```json
{
  "total": 3,
  "online": 2,
  "offline": 1
}
```

The total always equals the sum of online and offline devices.

## Device Status

Device status is calculated when a request is processed.

Agents normally send a heartbeat every 30 seconds.

A device is online when its most recent heartbeat is less
than 90 seconds old and is not in the future.

A device is offline when its heartbeat is at least 90 seconds
old or has an invalid future timestamp.

Stopping an agent does not remove its device registration.

A subsequent successful heartbeat can restore online status.

## Timestamps

Device timestamps are represented in UTC using RFC 3339
with optional fractional seconds.

| Field | Description |
| --- | --- |
| created_at | Device registration time |
| updated_at | Last device record update |
| last_seen_at | Last recorded device contact |

## Response Headers

Device API JSON responses include:

    Content-Type: application/json; charset=utf-8
    Cache-Control: no-store

## Error Responses

| Status | Description |
| --- | --- |
| 200 | Successful request |
| 400 | Invalid request when detected |
| 404 | Device or endpoint not found |
| 405 | Unsupported HTTP method |
| 500 | Internal server error |

Device handler errors use the following JSON format:

```json
{
  "error": "device not found"
}
```

Routing errors generated by the HTTP server may use plain text.

Internal database errors are not exposed to clients.

## Security

The Management API is read-only.

Agent credentials, enrollment tokens, credential hashes,
and private certificate keys are not included in responses.

Management traffic is restricted to loopback interfaces.

Loopback binding is not a substitute for authentication.

The Management API is separate from the authenticated,
TLS-protected agent gRPC service.

## Current Limitations

- No administrator authentication.
- No management HTTPS support.
- No browser-origin protections.
- No remote management access.
- No pagination, filtering, or sorting controls.
- No device modification or deletion endpoints.
- No real-time event subscriptions.
- Device summaries are calculated from registered records.

These capabilities will be introduced in future milestones.
